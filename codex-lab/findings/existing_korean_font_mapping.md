# Existing Korean Font Mapping

Source of truth for byte mapping: `codex-lab/references/old_encoding_assets_for_mk/txt.cpp`.

The authoritative arrays are `FF7Text::caract_jp_c0` through `FF7Text::caract_jp_cc`. The lead byte selects the array (`C0` selects `caract_jp_c0`), and the trail byte is the zero-based index in that array. Empty strings remain unassigned slots.

## Validation Summary

- Parsed pages: `c0` through `cc`.
- Entries per page: exactly 256.
- Non-empty mappings: 2313.
- Empty slots: 1015.
- Adjacent C/C++ string literal warnings: 0.
- The suspected missing comma near `"귤","그","극"...` was not reproduced; the parser found normal comma-separated entries.
- Generated mapping: `codex-lab/generated/korean_mapping.json`.
- Empty-slot report: `codex-lab/findings/korean_mapping_empty_slots.csv`.
- Duplicate report: `codex-lab/findings/korean_mapping_duplicates.csv`.

## Font Artwork Source

Artwork style source: `codex-lab/work/hangulfont-ksx1001-gulim-shadow2x`.

That source atlas is packed KS X 1001 order and is not byte-compatible with `txt.cpp`. For example, the source atlas has `가` at packed `C0 00`, while `txt.cpp` maps `가` to `C0 21`. Therefore the first native page was generated by copying glyph pixels from the supplied Gulim shadow2x atlas into the exact `txt.cpp` destination slots.
